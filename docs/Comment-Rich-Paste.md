# วางเนื้อหาที่มีรูปแบบ

ก็อปตารางจากเมล / Excel / เว็บ แล้ววาง → **รูปแบบยังอยู่**

## ใช้ได้ที่ไหน

| ที่ | ช่องที่รับ | หน้าที่แสดง |
|---|---|---|
| **Ticket comment** | ช่องคอมเมนต์ | `TicketDetail` |
| **Incident / Project comment** | ช่องคอมเมนต์ | `CommentSection` |
| **Tools & Note** | ช่องเนื้อหา | `RichNote` — ผลถึง Knowledge, References, เอกสารอ้างอิงในโครงการ ด้วย |

ตัวรับการวางเป็น **hook ตัวเดียว** (`src/hooks/useRichPaste.ts`) ทุกที่เรียกตัวนี้
ถ้าก็อปโค้ดไปวางแต่ละหน้า กฎการกรองจะเริ่มต่างกันทีละนิด
แล้วหน้าที่ถูกลืมอัปเดตจะกลายเป็นช่องโหว่ที่ไม่มีใครรู้

## ปัญหาเดิม

คอมเมนต์เก็บเป็นข้อความล้วน ตารางที่ก็อปมาจึงแบนเป็นตัวหนังสือติดกันจนอ่านไม่ได้
ทั้งที่รูปแบบนั้น **คือ** สาระ (ใครทำอะไร ค่าเท่าไร)

## วิธีเก็บ — ต่อท้าย ไม่ใช่แทนที่

```
<ข้อความที่คนพิมพ์เอง>
<!--hd-html-->
<table>...</table>
```

เลือกแบบนี้เพราะ:

- **คอมเมนต์เก่าไม่มีเครื่องหมายคั่นนี้** จึงยังเป็นข้อความล้วนเหมือนเดิม — ไม่ต้องแปลงข้อมูลเก่า
- **ไม่ต้องเพิ่มคอลัมน์ใน SharePoint**
- ของเดิมที่เกาะบนข้อความล้วน — **@mention · จับวันที่แล้วคลิกสร้างงาน · พับเนื้อเมลเก่า** —
  ยังทำงานกับส่วนที่คนพิมพ์เองได้ครบ **ไม่ต้องเขียนใหม่บน HTML**

## ตอนวาง

ช่องพิมพ์ยังเป็นข้อความธรรมดา ส่วนที่วางมาขึ้นเป็นกล่องแยกใต้ลงมา **และเห็นเนื้อหาเลย**:

```
📋 เนื้อหาที่วางมา — จะถูกส่งพร้อมคอมเมนต์นี้
   [ย่อ]  [แก้เป็นข้อความ]  [ทิ้ง]
   ┌────────┬──────┐
   │ ชื่อ    │ ค่า  │
   ├────────┼──────┤
   │ a      │ 100  │
   └────────┴──────┘
```

**ไม่พับเป็นค่าเริ่มต้น** — ครั้งแรกที่ทำพับไว้ ผลคือช่องพิมพ์ว่างเปล่าและมีแต่ป้าย
บรรทัดเดียว ทั้งที่เนื้อหาถูกเก็บไว้จริง ดูเหมือนวางไม่ติด ซึ่งแย่กว่าไม่มีฟีเจอร์นี้

การ "เปิดใหม่ทุกครั้งที่วางเพิ่ม" ทำโดยจำว่าคนพับ *ก้อนไหน* ไว้ (`collapsedFor`)
ไม่ได้เก็บเป็น true/false — ไม่งั้นพับครั้งเดียวแล้ววางใหม่จะยังพับอยู่

- **แก้เป็นข้อความ** = ย้ายเป็นข้อความล้วนลงช่องพิมพ์ เพื่อแก้คำได้ (ตารางกลายเป็นคั่น tab)
- วางหลายครั้ง = ต่อกันด้วยเส้นคั่น ไม่ทับของเดิม

### เอาเฉพาะรูปแบบระดับ "บล็อก"

เกณฑ์ (`hasBlockMarkup`) คือ **ตาราง / รายการ / หัวข้อ / โค้ด / รูป** — ของที่พอแบนเป็น
ข้อความแล้วเสียความหมาย

**ตัวหนา ตัวเอน และลิงก์เดี่ยว ไม่นับ** เพราะการก็อป URL จากเบราว์เซอร์ได้ `<a>` ติดมา
ทุกครั้ง ถ้านับด้วย การวาง URL ธรรมดาจะกลายเป็นบล็อกที่แก้คำไม่ได้ และหลุดจากทาง
@mention / จับวันที่ ทั้งที่ไม่มีเหตุ — URL ในข้อความล้วนก็กดได้อยู่แล้ว

### ที่ทดสอบแล้วบนเบราว์เซอร์จริง (การวาง)

ยิง paste event จริงเข้า hook + component จริง:

| วาง | ผล |
|---|---|
| `<a href=...>` (ก็อป URL) | ไม่จับเป็นบล็อก · ไม่ `preventDefault` → ข้อความลงช่องพิมพ์ |
| `<table>` | จับเป็นบล็อก · **ตารางแสดงทันที ครบ 4 ช่อง** |
| กด "แก้เป็นข้อความ" | ได้ `ชื่อ	ค่า
a	100` ลงช่องพิมพ์ · บล็อกหายไป |

## ความปลอดภัย — เรื่องที่หนักที่สุดของงานนี้

HTML ที่ก็อปมาจากเว็บหรือเมลพา `<script>`, `onclick`, `javascript:` มาได้
**ถ้าเก็บดิบแล้วเอามาแสดง คนอื่นที่เปิดคอมเมนต์นั้นจะโดนรันโค้ดของคนวาง**

จึงกรองด้วย **รายการขาว** ไม่ใช่รายการดำ — รายการดำต้องเดาให้ครบทุกอย่างที่อันตราย ซึ่งเดาไม่ครบแน่

| | |
|---|---|
| แท็กที่เก็บ | `table` `tr` `td` `th` `ul` `ol` `li` `a` `img` `b` `i` `u` `p` `h1-6` `pre` `code` `blockquote` `hr` … |
| ทิ้งทั้งก้อน (รวมเนื้อใน) | `script` `style` `iframe` `object` `embed` `form` `input` `svg` `math` |
| แท็กไม่รู้จัก | ถอดเปลือก **เก็บข้อความข้างในไว้** |
| attribute | เก็บเท่าที่จำเป็น (`href` `src` `colspan`…) · **`on*` ตัดทุกตัวทุกแท็ก** · `style` ตัด |
| `href` | `https:` `mailto:` `tel:` `#/...` เท่านั้น |
| `img src` | `data:image/*` (≤400 KB) และ `https:` เท่านั้น |

**ใช้ `DOMParser` ไม่ใช่ regex** — HTML จากเมล/Word มีรูปแบบพิสดารได้มาก (แท็กไม่ปิด,
attribute ไม่มีเครื่องหมายคำพูด, `<!--[if gte mso 9]>` ของ Word) การแกะด้วย regex จะพลาด
และสิ่งที่พลาดคือช่องให้รันโค้ด

**กรองซ้ำตอนแสดงทุกครั้ง** ไม่ใช่เชื่อว่ากรองแล้วตอนวาง — ข้อมูลใน SharePoint แก้จาก
ทางอื่นได้ (หน้าเว็บ SharePoint, Power Automate, Add-in) การกรองครั้งเดียวตอนเขียน
ไม่ใช่หลักประกันตอนอ่าน

### ที่ทดสอบแล้วบนเบราว์เซอร์จริง

ยิง 20 กรณีเข้าโมดูลจริง แล้วแขวนผลลัพธ์ลง DOM จริงเพื่อดูว่ามีอะไรรัน:
`<script>`, `img onerror`, `svg onload`, `onmouseover`, `javascript:`,
`java<tab>script:`, `<iframe src=javascript:>`, `<style>`, `<form>`, `<object>`,
`style` attribute, `srcset`, ตารางไม่ปิดแท็ก, Word conditional comment,
`file:` / `cid:` img

ผล: **ไม่มีอะไรรันเลย · ไม่มี `on*` เหลือใน DOM · ไม่มี script/style/iframe/form/object เหลือ**
และตารางจริงผ่านมาครบโครงสร้าง

## รูปในเนื้อหาที่คัดลอกมาไม่ได้

`file:` (Word) · `cid:` (Outlook) · `blob:` ชี้ไปเครื่องหรือกล่องเมลของ**คนวาง**
คนอื่นเปิดก็ไม่เห็นอยู่ดี → แทนด้วยป้าย **"🖼️ (รูปในเนื้อหาไม่ได้ถูกคัดลอกมา)"**
พร้อมข้อความบอกจำนวน — ไม่ใช่ปล่อยกรอบรูปแตกให้เดาเอง

## อีเมลกับแจ้งเตือน

`plainSnippet()` แปลงเป็นข้อความล้วนก่อนเสมอ — **แท็กหลุดไปโผล่ในอีเมลไม่ได้**
และช่องตารางคั่นด้วย tab ไม่ใช่ติดกัน ไม่งั้นเลขสองคอลัมน์จะกลายเป็นเลขเดียวที่**อ่านผิด**ได้
ซึ่งแย่กว่าอ่านไม่ออก · `Title` ของแถวก็ใช้ข้อความล้วน

## เฉพาะของ Ticket: ตารางไปถึงลูกค้าเป็นตารางจริง

อีเมล `comment_added` เป็น HTML อยู่แล้ว จึงแนบบล็อกรูปแบบต่อท้ายไปเลย —
ลูกค้าเห็นตารางจริง ไม่ใช่ข้อความคั่น tab

พร้อมกันนั้นแก้ของเดิม: ข้อความที่คนพิมพ์เข้าเมลโดย**ไม่ได้หนีอักขระ HTML**
ข้อความอย่าง `<3` จึงทำให้เมลเพี้ยนได้ และเป็นช่องฉีด HTML เข้าเมลถึงลูกค้า
ตอนนี้หนี `&` `<` `>` ก่อนเสมอ ส่วนบล็อกรูปแบบผ่านตัวกรองมาแล้วตอนวาง

## เฉพาะของ Tools & Note

- ตอนกดแก้ไข **แยกบล็อกรูปแบบออกจากช่องพิมพ์** ไม่งั้นแท็กจะไปโผล่ให้แก้มือ
- ตัวอย่างบนการ์ดและ**ช่องค้นหา** ใช้ข้อความล้วน (`commentPlain`) — ไม่ค้นเจอชื่อแท็ก
- ไวยากรณ์เดิมของโน้ต (`## หัวข้อ` · `-` · `[[ไฟล์]]`) ยังทำงานกับส่วนที่พิมพ์เองครบ
  แต่**ใช้ในบล็อกรูปแบบไม่ได้** เพราะบล็อกนั้นไม่ผ่านตัวแกะไวยากรณ์
- บล็อกรูปแบบไม่พับตามหัวข้อ เพราะไม่ได้อยู่ในหัวข้อไหน
- โน้ตที่มีแต่ตารางไม่มีข้อความ ก็ยังแสดง ไม่ใช่คืนค่าว่าง
