# คลังความรู้สาธารณะ — เขียนใน Helpdesk เผยแพร่เป็นเว็บ

**ทรัพยากร → คลังความรู้** (`/knowledge`) — Agent ขึ้นไป

เขียนบทความแบบเดียวกับ KB ของ Citrix (อาการ → วิธีแก้ → สาเหตุ) แล้วกดสร้างเป็นเว็บ
สำหรับเผยแพร่ให้ลูกค้าและคนทั่วไป

```
เขียนบทความใน Helpdesk (เก็บใน SharePoint)
        │  ตั้งเป็น "เผยแพร่"
        ▼
กด "สร้างเว็บ" ──► ไฟล์ .zip (HTML ล้วน + รูป + ช่องค้นหา)
        │
        ▼
อัปโหลดขึ้น DirectAdmin ที่ public_html/kb/
        │
        ▼
itservices.co.th/kb/its000123.html  ← ลูกค้าเปิดได้เลย ไม่ต้อง login
```

## ทำไมต้อง export เป็นไฟล์ ไม่ใช่ทำเว็บอีกตัวที่ต่อฐานข้อมูล

**คนนอกไม่มี token ของ M365 จึงอ่าน SharePoint ไม่ได้เลย** ไม่ว่าจะเขียนเว็บใหม่กี่ตัว

ถ้าจะให้เว็บสาธารณะอ่านข้อมูลสดได้ ต้องมี **server ตัวกลาง** คอยดึงจาก SharePoint แล้วเปิดให้คนนอกอ่าน
ซึ่งแปลว่าต้องมีของอีกชิ้นให้ดูแล ต้องแพตช์ ต้องระวังไม่ให้ข้อมูลภายในรั่วออกไปด้วย

**export เป็น HTML ล้วนจบกว่า** — ไม่มีอะไรให้แฮก ไม่มีอะไรให้ล่ม เปิดเร็ว และ Google เก็บ index ได้

**ข้อแลก:** แก้บทความแล้ว **ต้องกดสร้างเว็บและอัปโหลดใหม่** เว็บที่เผยแพร่ไม่ได้อัปเดตตามอัตโนมัติ

## ลิสต์ที่ต้องสร้าง — `HD_KBArticles`

| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| `Title` | Single line of text | ชื่อเรื่อง |
| `ArticleCode` | Single line of text | รหัสบทความ เช่น `ITS000123` — **ใช้เป็นชื่อไฟล์และลิงก์** |
| `Product` | Single line of text | ผลิตภัณฑ์/ระบบ เช่น `Citrix VDA` |
| `Tags` | Single line of text | คั่นด้วย `,` |
| `Summary` | **Multiple lines of text (plain)** | อาการ / รายละเอียด |
| `Resolution` | **Multiple lines of text (plain)** | วิธีแก้ไข |
| `Cause` | **Multiple lines of text (plain)** | สาเหตุ (ไม่ใส่ก็ได้) |
| `ArticleStatus` | Choice | `Draft`, `Published` |

**และเปิด Attachments = Enabled** (รูปในบทความเก็บเป็นไฟล์แนบ)

## เขียนบทความ

ใช้ไวยากรณ์เดียวกับโน้ตและแหล่งอ้างอิงทั้งแอป:

| เขียน | ได้ |
|---|---|
| `## ชื่อหัวข้อ` | หัวข้อย่อยในบทความ |
| `- ข้อความ` | รายการ bullet |
| วาง URL ตรง ๆ | ลิงก์ (เปิดแท็บใหม่ พร้อม `rel="noopener"`) |
| `[[ชื่อไฟล์.png]]` | แทรกรูปตรงตำแหน่งนั้น |

- ปุ่ม **ดูตัวอย่าง** ในหน้าแก้ไข ดูผลก่อนบันทึก
- กดชื่อไฟล์แนบเพื่อ**แทรกรูปลงเนื้อหา** ไม่ต้องพิมพ์ชื่อเอง
- อ้างถึงไฟล์ที่ยังไม่ได้แนบ จะขึ้นเตือนตอนเขียน
- **รหัสบทความเดาให้อัตโนมัติ** (`ITS000001`, `ITS000002`, ...) แก้เองได้

## เผยแพร่

กดไอคอน 🌐 ในตาราง เพื่อสลับ **ฉบับร่าง ⇄ เผยแพร่**

ถ้าบทความยังไม่ครบ (ไม่มีวิธีแก้ / ไม่มีรหัส) จะเตือนก่อน **แต่ไม่บล็อก** — ยืนยันแล้วเผยแพร่ได้

> **เฉพาะบทความที่ตั้งเป็น "เผยแพร่" เท่านั้นที่จะขึ้นเว็บ** ฉบับร่างไม่ถูกใส่ลง zip เลย

## สร้างเว็บและนำขึ้น

1. **ตั้งค่าเว็บ** — ชื่อเว็บ, ชื่อองค์กร, อีเมลติดต่อ, ลิงก์กลับเว็บบริษัท
   (เก็บในเครื่องของคนที่กด ไม่ได้เก็บใน SharePoint — คนในทีมควรตั้งให้ตรงกัน)
2. กด **สร้างเว็บ (N)** → ได้ไฟล์ `kb-site-YYYY-MM-DD.zip`
3. แตกไฟล์ อัปโหลดทั้งหมดขึ้น DirectAdmin ที่ `public_html/kb/`

ในไฟล์ zip มี:

```
index.html              หน้ารวม + ช่องค้นหา
its000123.html          บทความละ 1 ไฟล์
style.css               ธีมเดียวใช้ทุกหน้า (รองรับโหมดมืดของเครื่องผู้อ่าน)
search.json             ข้อมูลค้นหา
assets/its000123/*.png  รูปของบทความนั้น
```

- **ค้นหาได้โดยไม่ต้องมี server** — ค้นจาก `search.json` ในเครื่องผู้อ่าน
- **เอาเฉพาะรูปที่ถูกอ้างถึงในเนื้อหา** ไฟล์แนบอื่นที่ไม่ได้ใช้จะไม่ขึ้นเว็บสาธารณะ
- ทุกอย่างที่ผู้ใช้พิมพ์ถูก escape ก่อนใส่ลง HTML

## ลิงก์ที่ส่งให้ลูกค้า

```
https://itservices.co.th/kb/its000123.html
```

**ลิงก์ยึดรหัสบทความ ไม่ใช่ชื่อเรื่อง** — เปลี่ยนชื่อเรื่องทีหลังลิงก์เดิมยังใช้ได้

⚠️ **อย่าเปลี่ยนรหัสบทความที่เผยแพร่ไปแล้ว** ลิงก์เก่าจะเสียทันทีที่สร้างเว็บครั้งถัดไป

## สิทธิ์

| ทำอะไร | ใคร |
|---|---|
| เขียน / แก้บทความ | Agent ขึ้นไป |
| เผยแพร่ / ลบ / สร้างเว็บ | Supervisor ขึ้นไป |

## ข้อควรระวัง

- **บทความขึ้นเว็บสาธารณะจริง** — ตรวจว่าไม่มีชื่อลูกค้า, IP ภายใน, ชื่อเครื่อง, หรือรหัสผ่าน
  ก่อนตั้งเป็นเผยแพร่ ระบบไม่มีทางรู้ว่าอะไรเป็นความลับ
- ลบบทความที่เผยแพร่แล้ว → ลิงก์เดิมจะ 404 หลังอัปโหลดเว็บครั้งถัดไป (ระบบเตือนก่อนลบ)
