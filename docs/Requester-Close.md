# ผู้แจ้งปิด Ticket ของตัวเองได้

## ปัญหา

EndUser ที่เปิด Ticket เอง พอปัญหาหายแล้ว **ปิดงานเองไม่ได้** — กล่อง "สถานะ / Reassign"
ทั้งใบเป็นของ agent ผู้แจ้งเห็นแต่สถานะ ต้องรอให้ทีมมาปิดให้ ทั้งที่เขาคือคนที่รู้ดีที่สุดว่าจบแล้วหรือยัง

## ตอนนี้: การ์ด "งานของคุณ"

แสดงให้**ผู้แจ้งที่ไม่ใช่ agent** — คนที่เป็นลูกค้าในช่อง หรือคนที่กดสร้าง Ticket

| สถานะตอนนี้ | ปุ่มที่เห็น |
|---|---|
| Open / In Progress / Pending | **ปัญหาแก้ไขแล้ว / ไม่ต้องดำเนินการต่อ — ปิดงาน** |
| Resolved (ทีมบอกว่าแก้แล้ว) | **ยืนยัน แก้ไขเรียบร้อยแล้ว — ปิดงาน** · **ยังไม่หาย — ขอให้ดูต่อ** (→ Open) |
| Closed | **ปัญหากลับมาอีก — เปิด Ticket นี้ใหม่** (→ Open) |

ให้ได้เฉพาะสิ่งที่เจ้าของปัญหาควรตัดสิน: **จบแล้ว / ยังไม่จบ** — assign, priority, Pending ยังเป็นของทีม

### เปิดกลับต้องบอกเหตุ ปิดไม่ต้อง

"ยังไม่หาย" กับ "กลับมาอีก" มีช่องให้พิมพ์ว่าติดอะไร และข้อความนั้น**ลงเป็นคอมเมนต์ในเธรด**ด้วย
ทีมจะได้เห็นเหตุผล ไม่ใช่แค่สถานะเด้งกลับมาเฉย ๆ · ส่วนปิดงานไม่บังคับเหตุผล บันทึกปิดงานเป็น "ผู้แจ้งปิดงานเอง"

### เปิดกลับ ไม่ใช่เปิดใหม่

ปัญหาเดิมกลับมา → เปิด Ticket เดิมกลับ ประวัติ/คอมเมนต์/ไฟล์อยู่ที่เดียว ไม่ต้องเล่าใหม่ตั้งแต่ต้น

## ทีมรู้เมื่อผู้แจ้งกด

ใช้ทางเดิมของ `updateStatus` ทั้งหมด: กระดิ่งในแอปถึงผู้รับผิดชอบ + ผู้แจ้ง + สมาชิก (ยกเว้นคนกด)
และเมล `ticket_status_changed` — ผู้แจ้งเป็นคนกดเองจึงไม่ส่งหาตัวเอง

## โค้ด

- [`src/utils/ticketOwner.ts`](../src/utils/ticketOwner.ts) — `isTicketRequester` `requesterActions` (12 เทสต์)
- `updateStatus(override?)` ใน `TicketDetail` รับสถานะตรง ๆ จากปุ่มของผู้แจ้ง โดยไม่แตะ state ของฝั่ง agent

## ไม่ต้องแก้อะไรใน SharePoint

> ผู้แจ้งต้องมีสิทธิ์ **Contribute** บน `HD_Tickets` อยู่แล้ว (เขาสร้าง Ticket ได้ = มี) — ถ้ากดแล้วขึ้น error สิทธิ์ ดูที่หน้า Diagnostic

## Incident ด้วย

การ์ด **"เคสของคุณ"** ในหน้า Incident สำหรับผู้แจ้งที่ไม่ใช่ agent — ผู้แจ้ง = คนกดสร้าง **หรือคนแจ้งสำรอง** (`ReporterEmail`)

| สถานะ | ปุ่ม |
|---|---|
| Open / In Progress | **ปัญหาแก้ไขแล้ว — ปิดเคส** (→ Resolved) |
| Resolved | **ยังไม่หาย — เปิดเคสนี้กลับ** (→ Open, ต้องบอกเหตุ → ลงคอมเมนต์) |

ใช้ทางเดิมของ `updateStatus` → เมล `incident_resolved` / `incident_status_changed` และกระดิ่งเหมือน agent กด
`isIncidentRequester` `incidentRequesterActions` — 7 เทสต์
