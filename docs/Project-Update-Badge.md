# ป้าย "มีอัปเดต" บนโปรเจกต์ที่ร่วมทีม

หน้าหลัก → **โปรเจกต์ที่ฉันร่วมทีม** เดิมเป็นชิปเรียบ ๆ ไม่มีอะไรบอกว่าอันไหนขยับ
ต้องเข้าไปดูทีละอันจึงจะรู้ ซึ่งไม่มีใครทำ

```
👥 โปรเจกต์ที่ฉันร่วมทีม   [2 อัปเดต]

( V #VDI  คอมเมนต์ใหม่ )   ← แดงทั้งชิป
( B #Backup  เคสใหม่ )     ← แดงทั้งชิป
( N #Nextcloud  Active )   ← ปกติ
```

## บอกว่า "อะไร" อัปเดต ไม่ใช่แค่ว่ามีอัปเดต

| ป้าย | หมายถึง |
|---|---|
| **งานใหม่** | Task ในโครงการขยับ |
| **เคสใหม่** | Incident ขยับ |
| **คอมเมนต์ใหม่** | มีคนคอมเมนต์ |
| **แก้ข้อมูล** | ตัวโครงการเองถูกแก้ |

ถ้าบอกแค่ "มีอัปเดต" ก็ยังต้องเข้าไปหาเองว่าอะไรเปลี่ยน

**ตัวเลขบนหัวข้อ** (`2 อัปเดต`) มีไว้เพราะกล่องนี้เลื่อนได้ — ชิปที่อัปเดตอาจอยู่พ้นสายตา

## ต้องดูของลูกด้วย

**SharePoint ไม่ขยับ `Modified` ของแถวโปรเจกต์เมื่อมีคนเพิ่ม task / เคส / คอมเมนต์**
ถ้าดูแค่ `Modified` ของโปรเจกต์ ป้ายนี้จะเงียบเกือบตลอด

ระบบจึงดู `PM_Tasks` · `PM_Incidents` · `PM_Comments` ด้วย แล้วเอาเวลาที่ใหม่สุด

**ยิงรวม 3 คำขอ** (เอา 200 แถวล่าสุดของแต่ละลิสต์) แล้วจับกลุ่มฝั่งเบราว์เซอร์ —
ไม่ยิงทีละโปรเจกต์ ซึ่งจะกลายเป็นหลายสิบคำขอทุกครั้งที่เปิดหน้าหลัก

## ป้ายหายเมื่อไหร่

**เปิดโครงการนั้น** → บันทึกเวลาที่เห็น → ป้ายหาย

บันทึก**หลังโหลดโครงการเสร็จ** ไม่ใช่ตอนเข้าหน้า — ถ้ายังโหลดไม่ได้ก็ยังไม่ได้เห็นอะไร

เก็บใน `localStorage` ต่อเครื่อง (`hdProjectSeen`) — **ไม่ต้องเพิ่มคอลัมน์ใน SharePoint**

## ที่จงใจทำ

**โปรเจกต์ที่ยังไม่เคยเปิด ไม่ติดป้าย** — ตอนโหลดครั้งแรกระบบตั้งเส้นฐานเป็น "เห็นแล้ว"
ถ้าปล่อยให้ติดพร้อมกันทั้งกระดานวันแรก **คนจะเลิกมองป้ายนี้ทันที** ซึ่งแย่กว่าไม่มีป้าย

จากนั้นความเคลื่อนไหวใหม่ทุกอย่างจะติดป้ายตามปกติ

## ข้อจำกัด

- **เก็บต่อเครื่อง** — เปลี่ยนเครื่องหรือล้าง site data แล้วเส้นฐานเริ่มใหม่ (ไม่ติดป้ายค้าง)
- ดูย้อนหลังแค่ **200 แถวล่าสุดต่อลิสต์** — โครงการที่เงียบมานานกว่านั้นจะใช้
  `Modified` ของตัวโครงการเอง
- **นับรวมความเคลื่อนไหวของทุกคน รวมของเราเอง** — คอมเมนต์ที่เราเพิ่งพิมพ์เองก็นับ
  (แต่พอเปิดโครงการก็หายทันที)
- ไม่ต้องตั้งค่าอะไรใน SharePoint
