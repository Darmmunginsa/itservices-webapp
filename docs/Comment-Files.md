# แนบไฟล์ในคอมเมนต์ — วาง ลาก และเปิดดูในหน้า

ใช้ร่วมกันทั้ง **Ticket / Incident / Project** เพราะทั้งสามใช้ `CommentSection` ตัวเดียวกัน

## แนบไฟล์ได้ 3 ทาง

| ทาง | หมายเหตุ |
|---|---|
| ปุ่มแนบไฟล์ | เดิม |
| **วาง (Ctrl+V)** ในช่องพิมพ์ | รวมภาพที่ capture หน้าจอมาแล้ววางเลย |
| **ลากมาทิ้ง** ที่กล่องคอมเมนต์ | กรอบประคลุมทั้งกล่อง ทิ้งตรงไหนก็ได้ |

ทั้งสามทางเข้าฟังก์ชันเดียวกัน (`addFiles`) — ถ้าแยกกันจะได้กฎการคัดไฟล์
และการตั้งชื่อที่ไม่ตรงกันสามชุด

### รับทุกนามสกุล

**ไม่กรองตามนามสกุล** — ให้ SharePoint เป็นคนปฏิเสธเอง เดาแทนมันจะกลายเป็น
บล็อกไฟล์ที่จริง ๆ แล้วอัปโหลดได้ ถ้า SharePoint ปฏิเสธ (บางนามสกุลถูกบล็อกที่ระดับ
tenant) จะขึ้น toast บอกชื่อไฟล์นั้น ไม่ใช่ fail เงียบ

ที่ปัดตกมีสองอย่างเท่านั้น:
- **0 ไบต์** — ลากโฟลเดอร์เข้ามาจะได้แบบนี้ ถ้าปล่อยไปจะไปพังตอนอัปโหลด
- **ใหญ่เกิน 100 MB** (`MAX_UPLOAD_BYTES`) — อัปโหลดผ่านเบราว์เซอร์แล้วมักค้าง

### ชื่อไฟล์

รูปที่วางจากคลิปบอร์ดมักชื่อ `image.png` **ทุกใบ** — เปลี่ยนเป็น
`pasted-2026-09-09-04-05-06.png` ให้แยกออก · ชื่อซ้ำในคิวเดียวกันเติม `-2`, `-3`
(เทียบแบบไม่สนตัวพิมพ์ เหมือนที่ SharePoint ทำ)

## เปิดดูในหน้า ไม่ต้องดาวน์โหลด

| ชนิด | ผลลัพธ์ |
|---|---|
| รูป | lightbox (เดิม) |
| **PDF** | `<iframe>` เปิดดูทั้งไฟล์ |
| **วิดีโอ / เสียง** | เล่นในหน้าเลย |
| **ข้อความ** (txt, log, csv, json, md, code) | อ่านในหน้า จำกัด 512 KB |
| Office (docx, xlsx, pptx) | ดาวน์โหลด — **แต่บอกเหตุผลว่าเบราว์เซอร์เปิดเองไม่ได้** |
| zip, exe, อื่น ๆ | ดาวน์โหลด |

ทุกชนิดใช้กรอบเดียวกัน (`FileViewer`) ต่างกันแค่ตรงกลาง — เพราะในสายตาคนใช้
มันคือการกระทำเดียวกัน "ขอดูไฟล์นี้หน่อย" · ปุ่มดาวน์โหลดยังอยู่เสมอ
การเปิดดูในหน้าไม่ได้แทนการเอาไฟล์ไปใช้ต่อ

### กุญแจสำคัญ: ต้องสร้าง blob ใหม่ให้ติดชนิดที่ถูก

SharePoint คืน `Content-Type: application/octet-stream` ให้ไฟล์แนบเกือบทุกไฟล์
**blob ที่เป็น octet-stream จะถูกเบราว์เซอร์สั่งดาวน์โหลด แม้จะเป็น PDF ก็ตาม**
ซึ่งเป็นอาการเดิมที่กำลังแก้อยู่พอดี

`spAttachmentBlob` จึงอ่านไบต์แรก → หาชนิดจริง → `new Blob([blob], { type })`
ก่อนสร้าง object URL

ลำดับความน่าเชื่อของชนิดไฟล์ (`resolveMime`):

1. **ไบต์แรกของไฟล์** (`sniffFile`) — เชื่อได้ที่สุด
2. **นามสกุล** — เมื่อไบต์บอกไม่ได้ (เช่น .txt ไม่มีลายเซ็น)
3. **header จากเซิร์ฟเวอร์** — ท้ายสุด และ `application/octet-stream` ถือว่า *ไม่ได้ตอบ*

ที่มีอยู่แล้ว) ยังไม่ได้ทำ
