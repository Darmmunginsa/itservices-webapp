# หมดเวลาใช้งานอัตโนมัติ + แจ้งเมื่อ token ตาย

แก้สองเรื่องที่ทำให้ "โหลดไม่ขึ้น" — และสองเรื่องนี้**ไม่ใช่เรื่องเดียวกัน**

| อาการ | สาเหตุ | ที่แก้ |
|---|---|---|
| ล็อกอินทิ้งไว้ยาว จนหน้าค้าง | ไม่มีการตัด session | ตัดอัตโนมัติเมื่อไม่ใช้งาน 1 ชม. |
| **กดอะไรก็ไม่ขึ้น ไม่มีอะไรบอก** | token ตาย (401) แต่ทุกหน้า `.catch(() => {})` | เด้งกล่องบอกว่าเซสชันหมดอายุ |

เรื่องที่สองคือ**ต้นเหตุจริง**ของที่พี่เจอ — ทุกหน้าจับ error ทิ้งเพื่อให้ลิสต์ที่ยังไม่ได้สร้าง
ไม่ทำแอปพัง ผลข้างเคียงคือ 401 ก็เงียบไปด้วย หน้าจอจึงว่างเปล่าแบบไม่บอกสาเหตุ

## 1. ตัดเมื่อไม่ใช้งาน

```
ไม่ขยับ 55 นาที          ครบ 60 นาที
      │                      │
      ▼                      ▼
┌──────────────┐         ออกจากระบบ
│  ⏰ 4:59      │         อัตโนมัติ
│ ยังอยู่ไหมครับ │
│[อยู่ต่อ][ออกเลย]│
└──────────────┘
```

- **นับจากครั้งสุดท้ายที่ขยับ** ไม่ใช่เวลาที่ล็อกอิน — คนที่ทำงานอยู่ไม่ถูกเตะออก
- นับจาก `pointerdown` / `keydown` / `wheel` / `touchstart`
- **แชร์กันข้ามแท็บ** — ทำงานอยู่แท็บเดียว อีกแท็บที่เปิดค้างไม่ทำให้ถูกตัด
- **เวลาเดินหน้าเท่านั้น** — ค่าค้างจากเซสชันก่อนไม่ทำให้คนที่เพิ่งล็อกอินถูกตัดทันที
- นาฬิกาเครื่องถูกปรับย้อนหลังก็ไม่ตัด
- ล็อกอินใหม่ = เริ่มนับใหม่

**บอกก่อนว่าข้อความที่พิมพ์ค้างไว้จะหายไปด้วย** — ไม่ใช่ให้รู้ตอนหาย

### เปลี่ยนเวลาได้

แก้ที่ `src/utils/idleSession.ts`

```ts
export const IDLE_LIMIT_MS = 60 * 60 * 1000   // 1 ชั่วโมง
export const WARN_BEFORE_MS = 5 * 60 * 1000   // เตือนก่อน 5 นาที
```

หรือส่งเป็น prop ให้ `<SessionGuard limitMs={...} warnMs={...} />` ใน `App.tsx`

## 2. token ตาย → บอกเลย

`services/sharepoint.ts` ห่อ `fetch` ทุกจุดไว้ (13 จุด) ถ้าเจอ **401 / 403**
จะเรียก handler ครั้งเดียว → เด้งกล่อง **"เซสชันหมดอายุแล้ว"** พร้อมปุ่มเข้าสู่ระบบใหม่

เรียกครั้งเดียวต่อการหมดอายุ เพราะหน้าหนึ่งยิงหลายลิสต์พร้อมกัน ไม่งั้นเด้งซ้ำหลายรอบ

## วิธีทดสอบเอง (ใช้ได้กับของจริง)

เปิด DevTools Console บนหน้าที่ล็อกอินอยู่ แล้วรัน:

```js
localStorage.setItem('hdLastActivity', String(Date.now() - 56*60*1000))
```

รอไม่เกิน 5 วินาที (รอบตรวจ) กล่องเตือนจะขึ้นพร้อมนับถอยหลัง ~4 นาที
กด **อยู่ต่อ** แล้วกล่องต้องหายและเริ่มนับใหม่

> ต้องรันหลังหน้าโหลดเสร็จ เพราะตอนล็อกอินระบบจะรีเซ็ตเวลาให้ใหม่

## สิ่งที่ทดสอบแล้ว / ยังไม่ได้

**ทดสอบแล้ว** — กติกาเวลาทั้งหมดมี **28 ข้อทดสอบ** ใน `npm run check:report`
คุมช่วงเตือน การนับถอยหลัง นาฬิกาย้อนหลัง ค่าเสียหายใน storage และค่าจากอนาคต

**ทดสอบกับเบราว์เซอร์แล้ว** — กล่องเตือนขึ้นตรงเวลา นับถอยหลังเดินจริง
และตัดออกเพียงครั้งเดียว (ไม่เด้งซ้ำ)

**ยังยืนยันไม่ได้** — ปุ่ม **"อยู่ต่อ"** ผมทดสอบในหน้าต่างที่ถูกซ่อน (`visibilityState: hidden`)
ซึ่งเบราว์เซอร์หน่วง timer ทำให้จับเวลาไม่ตรง ผลจึงไม่นิ่ง
ตอนกดจริงมีสองเส้นทางที่รีเซ็ตเวลา (`pointerdown` และ `onClick`) ซึ่งน่าจะทนกว่าที่เทสต์เห็น
แต่ยังไม่ได้พิสูจน์ — **ลองด้วยวิธีข้างบนก่อนใช้จริงจะแน่ใจกว่า**
