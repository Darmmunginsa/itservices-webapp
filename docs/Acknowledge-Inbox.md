# กล่องรอรับงาน (Acknowledge)

งานที่คนอื่นมอบหมายมาจะ**มาจ่อในกล่องนี้ก่อน** ยังไม่นับเป็นงานของเราจนกดรับ

```
งานของฉัน
┌──────────────────────────┬──────────────────────────┐
│ 📥 รอรับงาน   ③           │ [Tickets][Tasks][Incidents]│
│ ┌──────────────────────┐ │                          │
│ │ 🎫 VPN เข้าไม่ได้      │ │  งานที่รับแล้วอยู่ที่นี่     │
│ │ จาก หัวหน้า · 2 ชม.   │ │                          │
│ │ Ticket High [✓ รับงาน]│ │                          │
│ ├──────────────────────┤ │                          │
│ │ 🚨 เคสด่วน #VDI       │ │                          │
│ │ 📋 งานย่อย            │ │                          │
│ └──────────────────────┘ │                          │
└──────────────────────────┴──────────────────────────┘
```

## ทำไมต้องแยก

**"ถูกมอบหมาย" กับ "รู้แล้วและกำลังทำ" ไม่ใช่เรื่องเดียวกัน**

เดิมงานที่โยนมาโผล่ปนกับงานที่เรารับไว้แล้วทันที — แยกไม่ออกว่าอันไหนเราเห็นแล้ว
กับอันไหนมีคนโยนมาแต่เรายังไม่รู้ตัว และ**คนที่มอบหมายก็ไม่มีทางรู้ว่างานถึงมือหรือยัง**

## กติกา

| สถานะ | อยู่ไหน |
|---|---|
| ยังไม่กดรับ | **กล่องรอรับงานเท่านั้น** — ไม่โผล่ในรายการงานของเรา |
| กดรับแล้ว | ออกจากกล่อง เข้ารายการตามปกติ + **ส่งเมลแจ้งคนมอบหมาย** |

**ตัวเลขบนแท็บก็ไม่นับงานที่ยังไม่รับ** — เลขต้องตรงกับจำนวนที่เห็นในรายการ

เรียง**งานที่รอนานที่สุดขึ้นก่อน** เพราะเป็นตัวที่คนมอบหมายกำลังสงสัยว่าถึงหรือยัง

## ที่จงใจไม่เข้ากล่อง

| กรณี | เพราะ |
|---|---|
| **งานที่เราสร้างเองแล้วมอบหมายให้ตัวเอง** | เรารู้อยู่แล้ว จะให้กดรับก็ไม่มีความหมาย |
| งานที่ปิด/เสร็จแล้ว | ไม่มีอะไรให้ทำต่อ |
| งานของคนอื่น | ไม่ใช่ของเรา |

## ปุ่มรับงานมี 3 ที่ — ส่งเมลชุดเดียวกัน

1. **กล่องรอรับงาน** (หน้างานของฉัน)
2. **หน้า Ticket** — ปุ่ม "รับทราบ"
3. **การ์ด Task ในหน้าโครงการ** — ปุ่ม "รับทราบ"

ทั้งสามเรียก `services/ackNotify.ts` ตัวเดียวกัน — ถ้าต่างที่ต่างส่งเอง จะกลายเป็นว่า
กดจากบางที่แล้วคนสั่งงานไม่ได้รู้ ซึ่ง**แย่กว่าไม่ส่งเลย** เพราะคนกดเชื่อว่าแจ้งไปแล้ว

## ⚠️ ต้องทำใน SharePoint

### 1. เพิ่มคอลัมน์ใน `PM_Incidents`

| คอลัมน์ | ชนิด |
|---|---|
| `IsAcknowledged` | **Yes/No** |
| `AcknowledgedBy` | Single line of text |
| `AcknowledgedDate` | Date and Time (Include Time) |

`HD_Tickets` และ `PM_Tasks` **มีอยู่แล้ว** ไม่ต้องทำอะไร

> ยังไม่เพิ่ม → Incident จะไม่โผล่ในกล่อง (ถือว่ายังไม่ได้มอบหมายให้รับ)
> และการกดรับ Incident จะไม่สำเร็จ ส่วน Ticket/Task ทำงานปกติ

### 2. เพิ่ม template `work_acknowledged` ใน `HD_EmailTemplates`

Subject + Body มีให้แล้วใน `email-templates-html.md` หัวข้อ **7. Work Acknowledged**

> ยังไม่เพิ่ม → **กดรับงานได้ปกติ** แต่เมลไม่ออก และหน้าจอจะบอกว่ายังไม่ได้เปิด template ตัวไหน

## ตัวแปรในเมล

`{{work_kind}}` `{{work_title}}` `{{agent_name}}` `{{from_name}}` `{{due_date}}` `{{tag}}` `{{status}}` `{{link}}`

ค่าที่ไม่มีจะอ่านออก (`-` / `ไม่ได้กำหนด`) **ไม่ปล่อยเป็นช่องว่างกลางเมล**

## ข้อจำกัด

- **งานเก่าที่มอบหมายไว้ก่อนหน้านี้และยังไม่เคยกดรับ จะเด้งเข้ากล่องทั้งหมด** —
  เป็นพฤติกรรมที่ถูกตามกติกาใหม่ แต่ครั้งแรกอาจเห็นเยอะ กดรับรวดเดียวได้เลย
- **Task ยังไม่มีหน้าของตัวเอง** — กดชื่อในกล่องจะเปิดหน้าโครงการ
- คนที่ไม่ใช่ Agent (ผู้แจ้งทั่วไป) จะเห็นกล่องว่างเสมอ เพราะไม่มีงานถูกมอบหมายให้
